# /engine — DAG execution engine (C++ / MPI)

The execution kernel of the baseline: it deserialises a DAG conforming to
[`/shared/dag_schema.json`](../shared/dag_schema.json), applies the scheduling strategy under
test, runs the math under MPI, and emits timings.

**Current state: `src/main.cpp` is a hello-world stand-in.** It exists so the full `hpcctl`
lifecycle works end to end before the real engine is written. Replace `main.cpp` in place —
the contract below, the build layout, and every `hpcctl` default stay valid.

## What the engine must do (the contract)

- **Invocation:** `engine --dag <path>` — exactly what the sbatch script generated by
  `hpcctl submit` runs, under `srun --mpi=pmix`.
- **Rank layout:** `submit -n N` launches N+1 ranks on N instances with cyclic placement.
  **The highest rank (N, i.e. `size - 1`) is the scheduler**; workers 0..N−1 get one
  instance each, and the scheduler wraps onto the first instance beside worker rank 0.
  Design accordingly: the scheduler rank deserialises the DAG, broadcasts, and dispatches;
  ranks 0..N−1 are workers.
- **Results go to the working directory.** Every job runs with cwd set to a per-job directory
  on the shared filesystem (`/shared/dags/results/<job id>/`). Write timings and telemetry as
  files in cwd — never construct result paths — and `hpcctl result <job id>` downloads them.
- **Binary lands at `build/bin/engine`** (CMake's `RUNTIME_OUTPUT_DIRECTORY`); `hpcctl deploy`
  rsyncs `engine/build/` to `/shared/engine/`, and `submit` executes
  `/shared/engine/bin/engine`.
- **Exit non-zero on failure** (the stand-in uses 2 for a missing `--dag`, 3 for an unreadable
  file, via `MPI_Abort`).

## What the engine must NOT do

Logical DAG validation. Shapes, ranks, acyclicity, and initialisation are fully checked by
`/vmath` at build time and again by `hpcctl submit` against the schema — a DAG with a logic
error never reaches the engine, by project contract. The engine owns only **runtime physics**:

- out of memory, MPI deadlocks and communication failures,
- schema *parsing* failures (malformed or version-mismatched JSON),
- Slurm preemption, NaN/Inf anomalies.

If the engine ever hits a logical error, that is a bug in `/vmath`, not here.

## Writing the MPI application

Available on every node (installed by the bootstrap script): GCC 13, CMake, Ninja, Open MPI
(`mpicc`/`mpicxx`), `nlohmann-json` (header-only, for the DAG JSON), and protobuf. The
skeleton every version of the engine keeps:

```cpp
MPI_Init(&argc, &argv);
// scheduler rank (size - 1): read --dag <path> (a file on the shared FS), parse, validate
//         schema version, broadcast the plan; abort with MPI_Abort(comm, code) on parse failure
// worker ranks (0 .. size - 2): execute assigned nodes, synchronise as the strategy requires
// scheduler rank: write timings to files in cwd, print a final status line to stdout
MPI_Finalize();
```

Sanity signal in stdout: the stand-in prints one `hello from rank R of N on <host>` per rank
and ends with `ENGINE_OK ranks=<N> …`. A rank-0-only run is the signature of an MPI stack
mismatch between compile time and launch time — keep some equivalent marker.

## Build and test locally (no cluster needed)

```bash
bash ../hpcctl/src/hpcctl/bootstrap/install_engine_deps.sh   # same script cluster nodes run
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build
mpirun -np 4 ./build/bin/engine --dag ../hpcctl/examples/bench-matmul-001.example.json
# expect: ENGINE_OK ranks=4 ...
```

**Build on an OS no newer than the cluster's** — a binary built against a newer glibc will not
run there. `.env` pins `HPCCTL_OS=ubuntu2404` to match the Ubuntu 24.04 dev box; keep the two
in lockstep.
